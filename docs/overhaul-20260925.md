# Advantage360 Pro software-engineering overhaul — 25 September 2026

> **Current profile note (25 September 2026):** this document records the baseline
> overhaul before the user explicitly requested home-row modifiers. The active
> configuration now uses the fast-typing HRM profile documented in
> [`hrm-profile-20260925.md`](hrm-profile-20260925.md). The five-layer architecture,
> JKL; navigation, NUM grid, symbols and system controls remain unchanged.

This document is the evidence trail and final design record for the current
`Adv360-Pro-ZMK` repository. It treats the whole repository — firmware source,
board definitions, validators, documentation, host integrations, generated layer
maps and build pipeline — as the product. The active firmware remains intentionally
small: five immediate layers and no timing-sensitive typing behaviors.

## 1. Executive summary

The repository was already far beyond the Kinesis stock keymap. It had a pinned
Kinesis ZMK fork, local board definitions, five coherent layers, physical Advantage360
rendering, static validators, behavior simulations, host-side integration retained
from an older profile, and prior compiled firmware artifacts.

The strongest parts were also the right design direction for this workload:

- plain QWERTY alphas with no delayed letter behaviors;
- dedicated modifiers rather than home-row mods;
- immediate momentary NAV/SYM/NUM/SYS layers;
- a right-hand **J K L ; = Left / Down / Up / Right** cursor cluster;
- a right-hand numeric grid centered on **UIO / JKL / M,.**, not YUI/HJK/NM,;
- a dedicated developer symbol layer rather than text-expansion macros;
- per-half direct boot/reset keys and a deliberately difficult Bluetooth-clear action;
- the exact Kinesis/refil ZMK revision pinned by commit rather than a mutable branch.

The overhaul therefore does **not** replace a strong architecture with a novelty.
It removes one remaining inconsistency: NAV was partly a primitive navigation layer
and partly a duplicated macOS application-shortcut bank. QWERT/G/ZXCVB now fall
through to BASE on NAV, while the dedicated thumb Command/Control keys handle
normal application shortcuts. This reduces memorization, removes macOS-only
redundancy, and makes the layer more coherent on Linux and Windows.

The selected-host Bluetooth clear combo is also hardened with
`require-prior-idle-ms = <300>`. It remains SYS-only and bilateral, but now it also
refuses to arm immediately after ordinary typing. Validators enforce both the new
safety gate and the JKL; contract.

No home-row mods, bottom-row mods, tap dances, sticky modifiers, text macros or
large combo set were added. Current upstream ZMK has good tools for tuning these,
but the Kinesis fork has open reports specifically involving positional hold-tap,
and reliability is more valuable here than saving a few dedicated keys.

## 2. Research findings

### 2.1 Firmware baseline: Kinesis is not generic upstream ZMK

The active repository pins:

- `refil/zmk@f1d5fc736bdbdde11df0ec77114c6a398ee1252b`
- the repository's historical frozen build manifest resolves Zephyr to
  `dacab4875df72109b96cc8977547a0dc04875bcd`

Kinesis's current V3.0 changelog lists `adv360-z3.5-2` as the active base branch
since February 2025. That branch includes the January 2025 upstream rebase plus
Kinesis-specific split/RGB/Clique work and the 15 ms debounce change. The design
therefore validates behavior against the pinned Kinesis/refil source, not only
against today's upstream documentation.

Primary sources:

- Kinesis V3.0 changelog: https://github.com/KinesisCorporation/Adv360-Pro-ZMK/blob/V3.0/CHANGELOG.md
- Kinesis support: https://kinesis-ergo.com/support/kb360pro/
- pinned ZMK tree: https://github.com/refil/zmk/tree/f1d5fc736bdbdde11df0ec77114c6a398ee1252b

Kinesis's support page currently lists the February-2025 factory line and an
experimental July-2026 string-macro firmware. This configuration does not migrate
to the experimental string-macro line because keyboard-level text macros are not
needed for the target workflow and such a migration would mix an engine change
with a layout redesign.

### 2.2 Split behavior and latency

Upstream ZMK documents the central/peripheral model clearly: the central owns
layer/keymap state and the peripheral sends position events to it. BLE split
transport adds about 3.75 ms average and 7.5 ms worst-case latency to peripheral
input. The central also consumes more power.

Source: https://zmk.dev/docs/features/split-keyboards

This matters because the preferred JKL; cluster is physically on the right
peripheral. The few milliseconds of split transport are accepted in exchange for
the requested and ergonomically familiar right-hand cluster. The layout does not
add timing-sensitive J/K/L/; dual-role behaviors on top of that transport.

Reset/bootloader behaviors have source locality, but ZMK also documents that a
combo invoking a source-local behavior runs it on the central. That is why this
repository keeps **direct physical left/right SYS boot/reset keys**, instead of
pretending a bilateral combo can select a half.

### 2.3 Hold-tap and home-row mods

Current upstream ZMK supports `tapping-term-ms`, `quick-tap-ms`, multiple flavors,
`require-prior-idle-ms`, positional `hold-trigger-key-positions`, and
`hold-trigger-on-release`:

- https://zmk.dev/docs/keymaps/behaviors/hold-tap
- https://zmk.dev/docs/config/behaviors

The pinned Kinesis/refil tree contains the same relevant hold-tap properties.
That means home-row mods are syntactically possible. It does **not** mean they are
the production choice for this board.

Two still-open Kinesis-repository reports are directly relevant:

- #596 reports `hold-trigger-key-positions` not preventing home-row-mod typing
  misfires on Advantage360 firmware:
  https://github.com/KinesisCorporation/Adv360-Pro-ZMK/issues/596
- #815, opened February 2026, reports incorrect positional behavior for several
  bottom-row positions:
  https://github.com/KinesisCorporation/Adv360-Pro-ZMK/issues/815

These are user reports, not proof of a universal firmware defect, but they are
specific enough to reject positional HRMs as the default for a production layout
whose first requirement is reliability.

A separate open September-2026 issue (#858) reports a BLE/macOS failure for comma,
period and slash when **all four** Shift+Ctrl+Alt+GUI modifiers are simultaneously
held on current Kinesis firmware. Three-modifier combinations reportedly work.
This design does not create a Hyper key or rely on four-modifier chords:
https://github.com/KinesisCorporation/Adv360-Pro-ZMK/issues/858

### 2.4 Community patterns: useful principles, not templates

Representative expert configurations confirm several transferable patterns:

- Miryoku: small purpose-specific layers, thumb layer access, home-row modifiers,
  and strong spatial consistency. https://github.com/manna-harbour/miryoku_zmk
- Sunaku's Glove80 configuration: extensive bilateral HRM tuning, per-OS modifier
  strategy, and dedicated ergonomic layers. https://github.com/sunaku/glove80-keymaps
- LevNas: current "timeless" HRMs using a 150 ms prior-idle gate and positional
  logic. https://github.com/LevNas/zmk-config

Those configurations are valuable evidence that HRMs can be excellent on other
hardware/firmware combinations. They do not override the Advantage360-specific
issues above, and a 76-key Advantage360 has much less pressure to overload alpha
keys than a 34–36-key board.

### 2.5 Other ZMK behaviors considered

Current ZMK supports Caps Word, sticky keys/layers, key repeat, mod-morph, tap
dance, macros and conditional layers. The production design deliberately uses
only what provides clear value:

- **Caps Word: yes** — excellent for `CONSTANT_NAME` / environment identifiers.
- **Sticky modifiers: no** — dedicated physical modifiers are already good and
  stateful modifiers add cognitive cost.
- **Key repeat: not bound** — useful in some compact layouts, but no prime key is
  worth spending until a real workflow demonstrates the need.
- **Tap dance / mod-morph: no** — unnecessary hidden timing/state on a large board.
- **Conditional/tri-layer: no** — SYS already fits without requiring two layer
  holds.
- **Macros: no text macros** — editors/snippets are context-aware and easier to
  version/test than keyboard-level language snippets.

Behavior overview: https://zmk.dev/docs/keymaps/behaviors

### 2.6 Power

The redesign adds no polling feature, pointer motion, or communication-heavy
behavior. The only new runtime condition is a single combo prior-idle check on the
central, which is not a meaningful battery driver. Radio role and lighting dominate.
Kinesis currently gives a rough guide of 2–3 weeks with backlighting enabled and
2–3 months disabled. The repository retains white backlight off at startup, low
indicator underglow, and idle auto-off.

Kinesis battery guidance: https://kinesis-ergo.com/support/kb360pro/

## 4. New architecture

### Layer 0 — BASE

**Purpose:** zero-surprise typing and ordinary shortcuts.  
**Activation:** default.  
**Deactivation:** never; higher momentary layers temporarily override it.  
**Primary functions:** QWERTY, Escape, Tab, Caps Word, dedicated modifiers,
Backspace/Delete/Enter/Space, physical arrows and direct brackets/parentheses.

### Layer 1 — NAV

**Purpose:** universal cursor/editing primitives with macOS-first text motion.  
**Activation:** hold left middle thumb position 52.  
**Deactivation:** release position 52.  
**Primary functions:**

- A/S/D/F = Ctrl / Option / Command / Shift
- **J/K/L/; = Left / Down / Up / Right**
- H / quote = macOS line start/end (Cmd+Left/Right)
- U / P = macOS word left/right (Option+Left/Right)
- Y / backslash = macOS document top/bottom (Cmd+Up/Down)
- I / O = Page Down / Page Up
- N / M = Option+Backspace / Option+Delete
- comma / period = Backspace / Delete
- slash = Cmd+Backspace
- bottom-left = Home / End / Ctrl+Home / Ctrl+End / Insert
- QWERT, G and ZXCVB fall through to BASE; app shortcuts use the physical
  Command/Control modifiers instead of a hidden NAV shortcut bank.

### Layer 2 — SYM

**Purpose:** individual, repeatable developer punctuation.  
**Activation:** hold right middle thumb position 53.  
**Deactivation:** release position 53.  
**Primary functions:** paired braces/brackets/parentheses, angle brackets,
colon/semicolon, quotes, underscore/equal, shell operators, math operators and
special characters. No language keyword or multi-character text macros.

### Layer 3 — NUM

**Purpose:** fast, locale-stable numeric entry.  
**Activation:** hold large left thumb position 66.  
**Deactivation:** release position 66.  
**Primary grid:** **U I O = 7 8 9; J K L = 4 5 6; M , . = 1 2 3; right Space = 0.**
Y/P = divide/multiply, H/semicolon = minus/plus, quote = equals, slash = ordinary
dot. Digits/operators use keypad usages where appropriate.

### Layer 4 — SYS

**Purpose:** infrequent device/system controls.  
**Activation:** hold bottom-right position 75.  
**Deactivation:** release position 75.  
**Primary functions:** F1–F12, media/brightness, lighting, USB/BLE output, BT
profiles, direct left/right reset and bootloader. Selected Bluetooth bond clear is
SYS-only + bilateral outer-top chord + 300 ms prior-idle guard.

### Direct answers to the 28 required design questions

1. **Thumb keys:** 65 Bspc, 66 NUM, 67 Del, 52 NAV; 53 SYM, 68 Del, 69 Enter,
   70 Space (NUM: 0); upper thumbs 35/36 Cmd/Ctrl and 37/38 Ctrl/Cmd.
2. **Shift:** dedicated outer left/right Shift; NAV F is a navigation-layer Shift.
3. **Control:** mirrored upper thumb Ctrl plus NAV A.
4. **macOS Command:** mirrored upper thumb Command plus NAV D.
5. **Option/Alt:** inner home positions 34/39 plus NAV S.
6. **Home-row mods:** no.
7. **Positional hold-taps:** no in production; current Kinesis issue evidence is
   not strong enough to trust them here.
8. **Sticky modifiers:** no by default; dedicated modifiers are simpler.
9. **Caps Word:** yes, with underscore/keypad digits/backspace/delete continuation.
10. **Combos:** one maintenance combo only; no typing combos.
11. **Symbol architecture:** one dedicated momentary SYM layer with spatial pairs
    and individual punctuation, no text expansion.
12. **Navigation architecture:** momentary NAV, ASDF modifiers, **JKL; arrows**,
    adjacent macOS word/line/document helpers, generic Home/End alternatives.
13. **Number architecture:** keypad-style grid physically centered on UIO/JKL/M,.
    with thumb 0 and nearby operators.
14. **macOS/Linux differences:** keep one physical layout; macOS gets dedicated
    Option/Cmd motions, Linux composes Ctrl/Shift with JKL; and uses Home/End.
15. **Windows:** same universal base; compose Ctrl/Alt/Shift/GUI normally; remote
    numeric entry may require Num Lock.
16. **Escape:** dedicated BASE key left of A; transparent through layers.
17. **Backspace:** large left thumb 65; NAV comma and NUM right thumb 68 provide
    context-specific copies.
18. **Delete:** small lower thumbs 67/68; NAV period.
19. **Enter:** large right thumb 69.
20. **Tab:** outer left Q-row plus mirrored inner-right Q-row; Shift+Tab uses
    ordinary Shift or NAV F with Tab.
21. **Word navigation:** macOS NAV U/P; Linux/Windows NAV A(Ctrl)+J/;.
22. **Line navigation:** macOS NAV H/quote; Linux/Windows bottom-left Home/End.
23. **Selection:** add NAV F(Shift) to character/word/line/document motions; e.g.
    F+J/; character, F+S+J/; macOS word, F+D+J/; macOS line.
24. **Paired brackets:** SYM A/S/D = `{ [ (` and K/L/; = `) ] }`, with G/H =
    `< >`; this preserves a readable mirrored opening/closing model.
25. **`$ _ - | \\`:** `$` has left-hand SYM locations; `_` is SYM J; `-` is
    BASE top-right and SYM C; `|` is SYM R/M; `\\` is BASE backslash and SYM E/P.
    This gives both direct familiar positions and layer alternatives.
26. **Bluetooth protection:** SYS layer requirement, bilateral chord, 150 ms chord
    timeout and 300 ms prior-idle gate; it clears only the selected host bond.
27. **Existing parts retained:** five-layer architecture, dedicated modifiers,
    thumb plan, JKL; NAV, UIO/JKL/M,. NUM, symbol geometry, Caps Word, board/radio/
    sleep/HID settings, per-half recovery, pinned firmware revision, Studio choice.
28. **Popular ideas not adopted:** HRMs/bottom-row mods, widespread combos,
    sticky-mod default, tap dance, tri-layers and macro-heavy IDE/SQL/PowerShell
    banks. They add timing/state/maintenance cost without enough benefit on a
    76-key Advantage360, and HRM positional behavior has Kinesis-specific reports.

## 6. Modifier strategy

The production choice is a **dedicated/hybrid modifier strategy**, not home-row
mods:

- plain Ctrl/Cmd on upper thumbs for normal shortcuts;
- plain Option on inner home keys;
- plain Shift on both outer Shift keys;
- NAV exposes Ctrl/Option/Cmd/Shift on ASDF so text selection/navigation chords
  can stay spatially close to the right-hand JKL; cluster.

Why this beats the alternatives here:

- **Classic-only:** predictable but would put too much modifier work on outer
  fingers and waste the Advantage360 thumb cluster.
- **Home-row/bottom-row mods:** save keys but introduce resolution logic and have
  board-specific issue reports on the Kinesis fork.
- **Pure thumb mods:** the thumbs already own Space, Enter, Backspace, Delete and
  three layer holds; forcing Shift/Alt/etc. entirely onto thumbs creates awkward
  same-thumb conflicts.
- **Sticky modifiers:** useful accessibility/compact-board primitive but adds
  state and timeout semantics where simultaneous dedicated modifiers already work.

There are **no hold-tap timing parameters** in the final keymap because no active
hold-tap is used.

Do not build workflows around all-four Shift+Ctrl+Alt+GUI chords until Kinesis
issue #858 is resolved or independently disproved on this exact hardware/transport.

## 8. Cross-platform behavior

### macOS

macOS is first-class. Command and Control are thumb-accessible; Option is inner
home. NAV provides dedicated Option word movement and Command line/document
movement. QWERT/G/ZXCVB on NAV now fall through, so application actions such as
Cmd+C/V/X/Z/A/F/S/W/T/Q use the same physical modifiers and base letters as every
other shortcut instead of a second NAV mnemonic.

Use ABC/US while coding with SYM. The firmware cannot detect the active macOS
input source. The repository's local UCKeyTranslate audit found keypad digits and
operators suitable for NUM under ABC/US/Czech, but SYM remains US-keycode based.

### Linux

Base modifiers remain Ctrl/Alt/Super/Shift. JKL; remains the same arrow cluster.
For word selection/motion, compose NAV A (Ctrl) and NAV F (Shift) with J/; as the
application expects. Home/End and Ctrl+Home/End remain dedicated at the bottom-left
of NAV. Terminal applications may interpret Ctrl/Alt sequences themselves; the
keyboard intentionally does not bake shell-specific text macros.

### Windows

Command/GUI becomes the Windows key; Control and Alt are unchanged. Ctrl-based
copy/paste/undo and word navigation use the physical thumb Ctrl or NAV A. Home/End
and Ctrl+Home/End are explicit on NAV. Remote PowerShell sessions should use an
appropriate US remote layout for SYM and may require Num Lock for keypad digits.

### Necessary semantic differences

No firmware can make Option+Arrow (macOS word navigation), Ctrl+Arrow
(Windows/Linux word navigation), Cmd+Arrow (macOS line/document motion) and
Home/End (Windows/Linux conventions) semantically identical everywhere. The
chosen abstraction is **same cursor geometry, platform-appropriate modifier**,
with dedicated macOS accelerators because macOS is primary.

## 10. Migration guide

This revision is deliberately low-disruption.

**Day 1 — no retraining for core typing**

- BASE, thumbs, symbols and NUM are unchanged.
- Keep using J/K/L/; as Left/Down/Up/Right.
- Keep using ASDF as NAV Ctrl/Option/Cmd/Shift.

**Day 1–2 — stop using old NAV application shortcuts**

The old direct NAV QWERT and ZXCVB Cmd shortcuts are gone. Use the existing thumb
Command key with the ordinary base letter instead. Examples:

- Cmd+C: hold thumb Cmd, press C.
- Cmd+V: hold thumb Cmd, press V.
- Cmd+Shift+Z: hold thumb Cmd + Shift, press Z.
- Cmd+F/S/A/W/T/Q: same normal physical shortcut model.

This is the only meaningful muscle-memory disruption.

**Maintenance action change**

Bluetooth selected-bond clear now requires at least 300 ms of prior idle before
the bilateral SYS chord is eligible. This is intentional friction.

**After flashing**

Run the hardware checklist in `docs/setup.md`: each half's boot/reset, BLE/USB
output, all five profiles, sleep/wake, layer indicators, JKL; arrows, NUM keypad,
Caps Word, VS Code/terminal/Neovim, and remote Windows behavior.

## 11. Cheat sheet

| Hold | Function | Core |
|---|---|---|
| NAV (left middle thumb 52) | movement/modifiers | ASDF = Ctrl/Opt/Cmd/Shift; **JKL; = ← ↓ ↑ →** |
| SYM (right middle thumb 53) | programming symbols | ASDF = `{ [ ( :`; G/H = `< >`; JKL; = `_ ) ] }` |
| NUM (large left thumb 66) | numeric grid | UIO 789; JKL 456; M,. 123; Space 0 |
| SYS (bottom-right 75) | device/function/media | F1–F12, BT, USB/BLE, lighting, recovery |

Core thumbs: Bspc / NUM / Del | Del / Enter / Space. Upper thumbs: Cmd/Ctrl |
Ctrl/Cmd. Option: inner home keys. Shift: outer Shift keys.

Selection: NAV+F+JKL; for character selection. On macOS add NAV+S for word or
NAV+D for line/document-style Cmd movement. On Windows/Linux use NAV+A (Ctrl)
where Ctrl+Arrow is the platform word-navigation convention.

Bluetooth clear: pause ordinary typing, hold SYS, press both outer top keys within
150 ms. Only the selected host bond is cleared.

built at the same pinned ZMK revision, but it does not prove these final source
changes compile.

CI (`.github/workflows/build.yml`) is already set up to run `make validate`, fetch
the pinned west modules, execute native behavior simulations and build both halves.
A clean CI run or local `make` in the documented Docker/Podman environment is the
remaining build gate before flashing.

## 13. Changelog

### Added

- 300 ms prior-idle gate on the selected-host Bluetooth-clear combo.
- validator requirement that destructive combos include a meaningful idle gate.
- regression contract that NAV J/K/L/; is Left/Down/Up/Right.
- regression contract that NAV's former app-shortcut positions remain transparent.
- this current-web research/design/validation record.
- an explicit local-build preflight that reports a missing Docker/Podman runtime
  instead of accidentally trying to execute a command named `build`.

### Changed

- NAV is now strictly a navigation/modifier primitive layer rather than a mixed
  navigation + macOS application-shortcut layer.
- README, cheat sheet and generated layer diagrams reflect the final NAV behavior.

### Moved

- No physical key was moved. This is deliberate: the audit found the thumb,
  symbol, number and JKL; navigation geometry already strong.

### Removed

- NAV direct macOS application shortcuts from Q/W/E/R/T, G, Z/X/C/V/B.
  Equivalent normal shortcuts remain available through the existing dedicated
  Command/Control/Shift keys plus ordinary letters.

### Fixed

- Local `make` now fails with a clear Docker/Podman prerequisite message when no
  container runtime is installed.
- Reduced the chance of accidental Bluetooth-bond clearing during rapid keyboard
  use.
- Removed OS-specific shortcut duplication that conflicted with the stated goal
  of a simple cross-platform mental model.
- Made the user's explicit **JKL; — not HJKL —** navigation requirement a tested
  repository invariant.

---

### Final engineering conclusion

The best production Advantage360 configuration for this workload is not the one
with the most ZMK features. It is the one where high-frequency actions are easy,
rare/destructive actions are hard, and ordinary typing is never waiting for a
firmware timing decision. The existing repository had already converged strongly
in that direction. This revision tightens the remaining inconsistencies while
preserving the proven spatial model.
