# Research notes · 6 September 2026

Audience: a macOS Python/SQL software and data engineer using a wireless
Kinesis Advantage360 Pro and native VS Code. This implementation preserves QWERTY
and uses existing applications. The recommendations below are engineering choices,
not proof of a universally optimal layout or a measured health benefit.

| Evidence | Consequence for this configuration | Confidence / limitation |
|---|---|---|

| [Kinesis vendor notes](https://github.com/KinesisCorporation/Adv360-Pro-ZMK) describe special lighting behavior and layer indicators. | Retain the board definitions and current sleep/lighting defaults. | Upstream battery estimates cannot establish savings on this fork. |

## Inspection findings

The initial tree was clean on `V3.0` at `66d6b27`. Existing validation passed,
but did not catch NUM-lock usability, delayed Shift-click, stale home-row/macro
explanations, or missing Mac applications. Installed AeroSpace settings differed
from the checked-out fragment; the native VS Code configuration also contained
Neovim settings and J/K/L/; list-navigation bindings. The implementation preserves
that host environment and makes the firmware/editor/desktop ownership explicit.

Research used local configuration and installed command definitions, followed by
bounded primary-source searches of Kinesis, ZMK, Microsoft, Apple and AeroSpace.
Follow-up retrieval resolved vendor-version, pointing, modifier timing, pairing
and battery-reporting gaps. Retrieval stopped when those design decisions had
primary evidence; more general layout rankings would not resolve individual comfort.
No anecdotal keyboard-layout ranking is treated as ergonomic evidence.
